## 为什么需要前端工程化?
1. js全局作用域冲突(模块化)
2. 编码规范问题(eslint,stylint,prettier等)
3. 资源合并和压缩问题
4. 高版本js预发降级
核心就是三点问题：效率、规范、性能

## 前端模块化的发展进程
1. 第一阶段：全局function模式，将不同功能封装成为不同函数，缺陷：容易引起全局命名冲突
2. 第二阶段：全局namespace模式，通过对象封装模块，缺陷：外部能够修改模块内部数据
3. 第三阶段：IIFE模式，通过自执行函数创建闭包，缺陷：无法解决模块间相互依赖的问题
4. 第四阶段：IIFE模式增强，支持传入自定义依赖，缺陷：多依赖传入的时候，代码阅读困难，无法支持大规模的模块化开发，无特定的语法支持，代码简陋

## CommonJs规范
- Node.js默认模块化规范，每一个文件就是一个模块，有自己的作用域
- Node中的CJS模块加载采用同步加载的方式
- 通过require加载模块，exports或者module.exports输出模块
- 所有代码都运行在模块作用域，不会污染全局作用域
- 模块可以多次加载，第一次加载时会运行模块，模块输出结果会被缓存，再次加载的时候，直接从缓存结果中直接读取模块输出结果
```javascript
//app.js
const mod = require("./cjs");
const mod1=require("./cjs");
//cjs.js
function api() {
  return {
    data: [1, 2, 3],
  };
}

console.log(Date.now());//虽然上面引用了两次，但是这行打印语句只会执行一次，因为缓存了
module.exports = api;
```
- 模块加载的顺序就是模块在代码中出现的顺序
- 模块输出的值是值的拷贝，类似IIFE中的内部变量（CommonJs底层原理就是IIFE+Module Cache Map，每个文件都会被IIFE包一层，返回require,module这些宏变量）
```javascript
//app.js
const m = require("./cjs");
m.x=2;
console.log(m.x);//2
console.log(m.getX());//1
//cjs.js
var x=1;

module.exports={
	x,
	getX(){
		return x;
	}
}
```
```javascript
//使用IIFE的方式
const cjs=(function(){
	var x=1;
	return {
		x,//返回的是当前值的拷贝
		getX(){
			return x;//引用的是闭包中的x
		}
	}
})();
cjs.x=2;
console.log(cjs.x);//2
console.log(cjs.getX());//1
```
> cjs规范的代码如果想要在浏览器中运行，可以通过npm安装browerify工具，然后通过browerify工具对代码分别进行打包
