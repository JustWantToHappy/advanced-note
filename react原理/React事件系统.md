## React事件系统是如何工作的
1. 事件委托：react16以及之前，把所有的事件统一委托到document,react17开始委托到应用根节点root,不再挂载到document,不会给每一个DOM单独绑定真实事件
2. 当事件发生在具体的DOM节点上被触发后，根节点捕获到原生事件。react会根据原生事件的target，从触发元素向上遍历Fiber树，收集这条路径上所有绑定对应事件的回调函数，按照冒泡或者捕获的顺序，把回调放入队列中，然后批量执行。（document上所绑定的同一事件处理程序会将事件分发到具体的组件实例上。）
3. 传给事件处理函数的e不是原生对象，而是react封装的合成事件对象SyntheticEvent，e.stopPropagation()，只能阻止合成事件冒泡，不能阻止原生DOM事件冒泡
> react16以及之前使用事件池对合成事件的内存管理进行了优化，如果池子有合成对象，使用此合成对象，否则新建一个对象并放入事件池。react17开始每次都会new 一个合成对象
