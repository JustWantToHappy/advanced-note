## 执行上下文
执行上下文：一句话概括就是“代码”(全局代码，函数代码)执行前进行的准备工作，也称之为“执行上下文环境”

当 JavaScript 代码执行一段可执行代码(executable code)时，会创建对应的执行上下文(execution context)，它会在运行代码之前做一些准备工作，如确定作用域，创建局部变量等

### js中执行环境  
1. 全局环境
2. 函数环境
3. eval函数环境

与之对应的执行上下文栈按照分类有：
1. 全局执行上下文
2. 函数执行上下文
3. eval函数执行上下文

### 执行上下文栈
js引擎创建了执行上下文栈来管理执行上下文：程序执行进入一个执行环境的时候，它的执行上下文就会被创建，并推入执行栈中，程序执行完成，它的执行上下文就会被销毁，并从栈顶出栈，控制权交由下一个执行上下文

处于栈底的永远是全局环境的执行上下文，而处于栈顶的是当前正在执行函数的执行上下文

> 全局执行上下文只有一个，只有当页面被关闭之后它才会从执行栈中出栈，否则一直处于栈底

### 执行上下文生命周期
执行上下文的生命周期有两个阶段：
1. 创建阶段（进入执行上下文），函数被调用时，进入函数环境，为其创建一个执行上下文，此时进入到创建阶段
2. 执行阶段（代码执行）：执行函数中代码时，此时执行上下文进入执行阶段

#### 创建阶段
1. 创建变量对象(VO)
	- 确定函数的形参并赋值
	- 函数环境会初始化创建arguments对象并赋值
	- 函数声明并赋值
	- 变量声明、函数表达式声明未赋值
```javascript
function A(){}//函数声明,变量提升
const B=function(){}//函数表达式声明，不会变量提升
```
2. 确定this指向（调用者确定）
3. 确定作用域（词法环境决定）
```javascript
const foo=function(i){
	var a="hello";
	var b=function privateB(){};
	function c(){}；
}
foo(10);
//1. 创建执行上下文环境阶段
fooExecutionContext={
	vo:{
		i:10,
		arguments:{0:10,length:1},
		c:指向c那个函数,
		a:undefined,
		b:undefined,
	},
	this,
	scope,
}
```
## 作用域
作用域是指在程序中定义变量的区域，该位置决定了变量的生命周期，通俗的理解，**作用域就是变量和函数的可访问范围**，即作用域控制着变量和函数的可见性和生命周期

ES6之前js没有块级作用域，只有全局作用域和函数作用域
> var 声明会提升到函数作用域顶部，但块级作用域（{}）限制不了它,块级作用域中建议使用let、const变量

### 全局作用域
任何地方都能访问到的对象拥有全局作用域
- 最外层的函数和在最外层函数外面定义的变量拥有全局作用域；
- 所有未定义直接赋值的变量拥有全局作用域
```javascript
function foo(){
	name="sb"//拥有全局作用域
}
```
- 所有 window 对象的属性拥有全局作用域，例如 window.name、window.location、window.top 等

### 函数作用域
函数作用域就是在函数内部声明的变量，函数外部访问不到
### 块级作用域
块级作用域就是用花括号 {} 包裹的代码区域，内部用 let/const 声明的变量只能在花括号内访问，如下这些都会创建块级作用域，如`if(xxx){}`、`else{}`、`for(xxx){}`等
### 作用域链 
#### 自由变量
当前作用域中没有定义的变量，对于当前作用域来说，这个变量就是自由变量
```javascript
const a=1;
function foo(){
	console.log(a)//a就是foo函数作用域的自由变量
}
```  
#### 作用域链定义
定义：当查找变量的时候，会先从当前上下文的变量对象中查找，如果没有找到，就会从父级(词法层面上的父级)执行上下文的变量对象中查找，一直找到全局上下文的变量对象，也就是全局对象。这样由多个执行上下文的变量对象构成的链表就叫做作用域链。

#### 关于自由变量的取值
```javascript
var x=10;
function fn(){
	//从创建fn函数的作用域中取，无论fn函数将会在哪里调用
	//在函数声明的时候就决定了，而不是取决运行时，这就是静态作用域
	console.log(x);//结果为10，而不是20
}
function show(f){
	var x=20;
	(function(){
		f();//
	})();
}
show(fn);
```
### 作用域和执行上下文
js是解释性语言，js的执行分为：解释和执行两个阶段：

**解释阶段**
- 词法分析
- 语法分析
- 作用域规则确定

**执行阶段**
- 创建执行上下文
- 执行函数代码
- 垃圾回收

作用域与执行上下文最大的区别就是：**执行上下文在运行时确定，随时可能发生改变，作用域在定义时就确定了，无法发生改变**

## this
通俗来说this指向当前调用者对象，严格来说：
- 在函数体中，非显式或隐式简单调用函数时，在严格模式下，函数内的this会被绑定到undefined上，在非严格模式下会被绑定全局对象window/global上
- 一般使用new方法调用构造函数时，构造函数内的this会被绑定到新创建的对象上
- 一般通过call/apply/bind方法显式调用时，函数体内的this会被绑定到指定参数的对象上
- 一般通过上下文调用函数时，函数的this会被绑定到该对象上
- 在箭头函数中，this的指向是由外层作用域决定的
 
### 改变this指向
由于js中this指向受函数运行环境影响，指向经常改变，使得开发变得困难和模糊，所以在封装sdk或者写一些复杂函数的时候经常会用到this指向绑定，以避免出现不必要的问题

## 闭包
函数 + 它捕获的外部词法环境，当访问函数中的自由变量的时候，就会创建闭包（其实就是利用了作用域链的特性）

```javascript
for(var i=1;i<=3;i++){
	setTimout(()=>{
		console.log(i);//3次打印结果都是4，这是因为每次闭包保存的都是同一个i
	},1000)
}

//每次循环都是创建的新的块级作用域，let声明的变量在块级作用域中是唯一的
for(let i=1;i<=3;i++){
	setTimout(()=>{
		console.log(i);//3次打印结果分别是1,2,3
	},1000)
}

```
